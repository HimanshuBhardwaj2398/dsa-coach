Arrays & Hashing, explained

Brute force checks pairs one at a time. A hash map lets one lookup answer a whole question at once: has the partner I need appeared yet? This page builds that idea on the same (i, j) grid as the sliding-window and stack pages, counts it, and then makes you run it yourself.

Every state, count and answer on this page comes from running reference.py under Python's tracer. Each step checks the invariant, and the answers match brute force on 3,005 inputs (empty, single, duplicates, negatives, no answer).

Problem
Two Sum: return indices [i, j], i < j, with nums[i] + nums[j] == target.
Pointer
j: the column being examined. x = nums[j].
Need
need = target − x: the only value that can partner x.
State
seen: a dict from value to index.
Invariant
While column j is examined, seen holds exactly the values of nums[:j], the ones to the left of j.
Relies on
Values are hashable; a dict lookup costs O(1) on average.
Breaks if
You store x before checking (x pairs with itself), or you need every pair (the dict keeps one index per value).
Terminates
j goes up by 1 each pass: at most n passes.
Complexity
The busiest line runs at most n times at O(1) each: O(n) time and O(n) space.

3Count the line runs, read off the Big-O

The method is the same as on the other pages: runs of each line × cost of one run. The line with the largest product decides the Big-O, because the number of lines doesn't grow with n. The worst case is an input with no answer, so every column runs. Here that's nums = list(range(n)) with target = −1, and the counts below were measured with the tracer.

nbrute line 5 runshashing line 5 runs
  • Brute force. Line 5, the compare, runs n(n−1)/2 times at O(1) each, so O(n²).
  • Hashing. Line 5, need in seen, runs at most n times at O(1) on average (hash the key and look in one bucket), so O(n) time. The map holds at most n entries, so O(n) space. Average-case costs are in Python's time-complexity table.
  • Group Anagrams. Line 4, "".join(sorted(s)), runs n times, and sorting k letters costs O(k log k), so O(n · k log k). The busiest line is now the key computation, not the lookup.

5Three ways it breaks

  1. Store before you check. If seen[x] = j moves above the lookup, x can find itself. The edge-case preset shows why the order matters. You'll predict the wrong output in the check below.
  2. An unhashable key. A list can't be a dict key (TypeError: unhashable type: 'list'). Turn it into a string or a tuple: "".join(sorted(s)), or a tuple of 26 letter counts, which avoids the sort and makes Group Anagrams O(n · k).
  3. One slot per key. A dict keeps one value per key, so a later duplicate overwrites the earlier index. Two Sum survives because it checks before it overwrites. When you need every index or a count, store a list or a count.
