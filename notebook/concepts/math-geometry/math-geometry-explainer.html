Math & Geometry, explained

No data structure to discover: the work is exact index arithmetic. Keep boundaries that shrink after each use, and when a number is huge, halve it instead of counting it down.

Spot it

These problems test careful bookkeeping more than a clever idea: walk a matrix in a spiral, rotate it in place, add digits with a carry, raise x to the 2³¹-th power. Most bugs are off-by-one errors, so make the bookkeeping explicit: name the boundaries (top, bottom, left, right) and say when each moves.

Two tools recur. Shrinking boundaries: after a row or column is used, move that boundary inward, and check the boundaries still cross before the next side, so a single row or column isn't walked twice. Halving: xⁿ = (x²)^(n/2), so look at n's bits and square at each step: log n multiplications instead of n.

Ask yourself

  1. What are the boundaries, and when does each move? Top after the top row, right after the right column, and so on.
  2. Can a step run on an empty range? Re-check top <= bottom / left <= right before the bottom row and left column.
  3. Is the number too big to count down? Halve it: exponentiation by squaring, O(log n).
  4. Can it be done in place? Rotate = transpose + reverse each row; mark rows and columns in the first row and column.

Your plan card

Start
the boundaries are the matrix's edges.
One lap
top row left to right, then top += 1; right column down, then right -= 1.
Re-check
if a row is left, bottom row right to left, bottom -= 1; if a column is left, left column up, left += 1.
Stop
the boundaries cross: every cell is in out.

What stays true

The unvisited cells are exactly the rectangle rows top..bottom, columns left..right.

Why each move is safe

  • Each side walked is one edge of that rectangle; moving its boundary in removes exactly those cells.
  • After the top row and right column, the rectangle may be empty (a single row or column was left). The two checks stop the bottom and left walks from visiting cells twice.
  • Every lap removes at least one row or column, so the loop ends after at most m + n laps.

Relies on: updating each boundary right after its side is walked, and re-checking before the third and fourth sides.

Shrinking boundaries

The spiral traces. Rotate Image goes layer by layer with the same boundaries, or transposes and reverses each row.

for r in range(n):                 # transpose: swap across the diagonal
    for c in range(r + 1, n):
        m[r][c], m[c][r] = m[c][r], m[r][c]
for row in m:                      # then reverse each row: 90° clockwise
    row.reverse()

Count the work

Count how often each line runs; the line with the most runs decides the Big-O. Here that is if n % 2 == 1:.

Each turn halves n, so the loop runs once per bit of n: about log₂ n turns. Squaring n (from 2⁸ to 2¹⁶, 2³², 2⁶⁴) only doubles the count. Multiplying x by itself n times would need n − 1 multiplications. (In Python, the numbers themselves grow, so each multiplication gets slower; with a modulus they stay small. The table is measured with x = 1 for that reason: the count of turns doesn't depend on x.) The spiral visits each of the m · n cells once: O(m · n).

Where it breaks

  • No re-check before the bottom row or left column walks a single remaining row or column twice.
  • Rotating with a copy when the problem says in place. Transpose, then reverse each row.
  • Negative exponents need the reciprocal: power(1 / x, -n).
  • Carries processed left to right in digit arithmetic. Work from the least significant digit.
