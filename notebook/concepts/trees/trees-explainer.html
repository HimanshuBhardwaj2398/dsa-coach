Trees, explained

Ask each subtree one question and combine the two answers. A call returns the answer for its own subtree, so the root's call returns the whole answer.

Spot it

Most tree problems are one recursive function that returns the answer for the subtree it was given. Trust the two recursive calls, combine their answers at the node, and handle None. That is depth, size, sameness, inversion and balance.

Two variations cover most of the rest. Some answers need information from above (the bounds a BST node must fit, the largest value on the path), so pass it down as an argument. Some need to record something different from what they return (the diameter through a node), so return a height and update a best. When the question is about levels or the nearest node, go breadth-first with a queue.

Ask yourself

  1. What does a call return for its subtree? Name it in one phrase: its height, whether it is balanced, its largest path down.
  2. What does a node do with its children's answers? 1 + max(left, right), left and right and ..., a sum.
  3. Does a node need something from above? Then it is an argument: bounds, a running maximum, the depth.
  4. Is it about levels or nearness? Breadth-first: a queue, one level per round.

Looks like it, isn't

  • A graph with cycles. Tree recursion assumes each node is reached once. With cycles you need a visited set: graphs.
  • A heap. Stored as a tree, but you never recurse on it: you sift along one path.
  • All paths from root to leaf with a property. Still a tree, but you build each path: that is backtracking on a tree.

Base case
node is None: an empty subtree has depth 0.
Recurse

Combine

Answer

What stays true

Every call returns the depth of its own subtree, and nothing else.

Why each move is safe

  • The base case is right by definition: no nodes, depth 0.
  • If the calls on the children return their subtrees' depths, 1 + max(left, right) is this subtree's depth. That is the whole proof (induction on height).
  • Each call is on a smaller subtree, so the recursion reaches None and stops.

Relies on: subtrees not sharing nodes, which is what makes it a tree. Recursion depth equals the tree's height: a skewed tree of 10⁴ nodes needs an explicit stack or a higher recursion limit.

Where it breaks

  • Checking a BST against its children only misses a value deep in the left subtree that is larger than the root. Pass bounds down.
  • No None case crashes at the first leaf's child, or counts leaves wrong.
  • Returning the path through both children to the parent in max path sum: a parent can extend only one side.
  • Deep recursion on a skewed tree hits Python's recursion limit (about 1000). Use an explicit stack for very deep trees.
