2-D Dynamic Programming, explained

Two indices, one table. Each cell answers the question for two prefixes (or a cell of a grid), reads its neighbours above and to the left, and the bottom-right cell is the answer.

Spot it

When a subproblem needs two numbers to name it (a prefix of each of two strings, a cell of a grid, an item and a capacity, a day and a state), the table is 2-D. The method doesn't change: say what dp[i][j] means in words, find the last decision, and fill in an order where every cell it reads is already filled.

For two strings, the last decision is about their last characters: if they match, they can pair up (diagonal + 1); if not, one of them is dropped (the cell above or to the left). That one idea gives longest common subsequence, edit distance (with a third neighbour for replace) and distinct subsequences.

Ask yourself

  1. What two things name a subproblem? Prefix lengths i and j; a grid cell; items so far and remaining capacity.
  2. What does dp[i][j] mean, in words? 'The LCS of a[:i] and b[:j]', 'the ways to reach cell (i, j)'.
  3. Which neighbours does a cell read? Diagonal, up, left: fill row by row, left to right.
  4. Do I need the whole table? If a row reads only the row above, keep two rows: O(n) space.

Which fits?

Pick what you would reach for. A wrong pick shows the gap; pick again to move on.

Looks like it, isn't

  • One sequence. One index: 1-D DP.
  • A grid where you can move in all four directions. Cycles: the fill order breaks. That is BFS, or memoised DFS when values strictly increase.
  • Listing every path. Exponential output: backtracking.

The parts

Names

dp[i][j]
the length of the longest common subsequence of a[:i] and b[:j]
row 0, column 0
an empty prefix: the LCS is 0
a[i − 1], b[j − 1]
the last characters of the two prefixes (the table is shifted by one)

Your plan card

Match
a[i − 1] == b[j − 1]: pair them, dp[i][j] = dp[i − 1][j − 1] + 1.
No match
drop one: dp[i][j] = max(dp[i − 1][j], dp[i][j − 1]).
Order
row by row, left to right: diagonal, up and left are filled first.
Answer
dp[len(a)][len(b)], the bottom-right cell.

What stays true

Every filled cell dp[i][j] equals the LCS length of a[:i] and b[:j].

Why each move is safe

  • If the last characters match, some longest common subsequence uses them as its last pair; the rest is an LCS of the shorter prefixes: diagonal + 1.
  • If they differ, they can't both be the last pair, so one of them is unused: the answer is the better of dropping a's last character (up) or b's (left).
  • Row-major order fills (i − 1, j − 1), (i − 1, j) and (i, j − 1) before (i, j).

Relies on: the answer for two prefixes depending only on shorter prefixes. With a third string, the table becomes 3-D.

The family

Name the two indices and the last decision; the rest is the same table.

Two strings, three neighbours

LCS above. Edit distance: 1 + min(up, left, diagonal) on a mismatch, the diagonal on a match. Distinct Subsequences counts: diagonal + up on a match. Interleaving String and regex matching use the same grid of prefixes.

Longest Common Subsequence medium · Edit Distance medium · Distinct Subsequences hard · Interleaving String medium · Regular Expression Matching hard

Paths in a grid

dp[r][c] = dp[r − 1][c] + dp[r][c − 1], with obstacles set to 0. When moves go in all four directions but values strictly increase (Longest Increasing Path), memoised DFS gives the order instead.

Unique Paths medium · Longest Increasing Path in a Matrix hard

Items × capacity (knapsack)

dp[k][x] = ways or best using the first k items for total x. Rolled to one row: unbounded items loop x upward; 0/1 items loop x downward so an item isn't reused. Target Sum is subset sum after algebra.

Where it breaks

  • Mixing string and table indices a[i] vs a[i − 1]: the table has an extra row and column for the empty prefix.
  • Filling in an order that reads unfilled cells gives zeros where answers should be. Row by row, left to right.
  • 0/1 knapsack rolled to one row, looping capacity upward reuses an item. Loop downward.
  • Keeping the whole table when one row would do uses m · n memory for nothing; reconstructing the subsequence does need it.
