Backtracking, explained

Build every answer one choice at a time: choose, recurse, undo. The calls trace a decision tree, and pruning cuts off whole branches that can't lead to an answer.

Spot it

Backtracking is depth-first search over partial solutions. Each call makes one decision (take this item or not, which letter goes here, where the next queen goes), recurses, then undoes it so the next option starts from the same state. The calls form a decision tree; the answers are its leaves.

Reach for it when the problem asks for all the combinations, subsets, permutations or placements, or when the input is small (n ≤ 20 or so) and the space is exponential anyway. If it only asks *how many* or *the best*, check whether the subproblems overlap: then it is dynamic programming.

Ask yourself

  1. What is one decision? Take or skip nums[i]; which unused value goes next; which column for this row's queen.
  2. What is a partial solution, and when is it complete? The path so far; complete at depth n, or when the target is met.
  3. What must be undone after recursing? Pop the path, unmark the cell, remove from the used set.
  4. What can be pruned? A sum already past the target, a letter that doesn't match, a queen under attack.

Which fits?

Pick what you would reach for. A wrong pick shows the gap; pick again to move on.

Looks like it, isn't

  • Count the subsets with a given sum. A count, with overlapping subproblems (index, remaining sum): DP, unless n is tiny.
  • Shortest path in a grid. Backtracking finds every path; BFS finds the shortest one directly.
  • Next permutation. One step of rearranging, not all permutations: a scan from the right.

Your plan card

Leaf
i == len(nums): every item is decided, so record path[:].
Choose
take nums[i]: append it and recurse on i + 1.
Undo
pop it, so the path is exactly as it was before the choice.
Other branch
skip nums[i]: recurse on i + 1 with the path unchanged.

What stays true

On entry to a call, path holds one choice for each of nums[:i], in order, and nothing else.

Why each move is safe

  • Every subset is a sequence of take-or-skip decisions, one per index, so each leaf is one subset and each subset is one leaf.
  • Popping after the first recursive call restores the invariant for the second, so the skip branch starts from the same path.
  • Recording path[:] stores a copy; path itself keeps changing, and storing it would leave every entry equal to the final, empty path.

Relies on: undoing exactly what was done, in reverse order. The work is exponential by design: prune early to cut whole subtrees.

Every call starts with the leaf check, and the decision tree has 2ⁿ leaves and 2ⁿ − 1 inner calls: 2ⁿ⁺¹ − 1 runs in all. Each leaf also copies a path of up to n items. So two more items quadruple the count: exponential, as any algorithm that lists all 2ⁿ subsets must be.

Where it breaks

  • res.append(path) without copying stores the same list every time; at the end every entry is the final, empty path.
  • Forgetting to undo leaks a choice into the sibling branch: the skip branch still holds the taken value.
  • Duplicates without sorting and skipping lists the same subset or combination more than once.
  • Pruning after recursing explores the doomed subtree anyway. Check the bound before the call.
