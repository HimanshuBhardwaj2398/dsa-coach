1-D Dynamic Programming, explained

Name the subproblem, write how it is built from smaller ones, and fill a table in an order where every cell it reads is already there. Each subproblem is solved once.

Spot it

Dynamic programming fits when a problem asks for a best value or a count, its answer can be built from the answers to smaller versions of itself, and those smaller versions repeat (plain recursion would solve them again and again). Then solve each one once and keep it in a table.

Write it in five lines before coding (SRTBOT, from MIT 6.006): the Subproblem in words ('dp[i] = the most loot from houses 0..i'), the Relation between subproblems, a Topological order to fill them in, the Base cases, the Original problem's cell, and the Time. Most 1-D problems read either the last one or two cells (take or skip), or every earlier cell (best over all choices).

Ask yourself

  1. What is dp[i], in words? 'The most loot from the first i houses', 'the fewest coins for amount i'.
  2. What is the last decision? Rob house i or not; which coin was used last; where the last word starts.
  3. Which cells does dp[i] read? Only smaller ones, so filling left to right works.
  4. Count or best? Counts add over the choices; best takes max or min.

Which fits?

Pick what you would reach for. A wrong pick shows the gap; pick again to move on.

Looks like it, isn't

  • All combinations or paths themselves. Exponential output: backtracking. DP only counts or optimises.
  • A greedy choice with an exchange argument. Jump Game needs only the farthest reach; DP would work but is slower.
  • Two sequences, or a grid. Two indices: 2-D DP.

The parts

Names

dp[i + 2]
the most loot from houses 0..i (two padding cells at the front stand for 'no houses')
dp[i + 1]
skip house i: the best from houses 0..i − 1
dp[i] + money
rob house i: it adds to the best from houses 0..i − 2

Your plan card

Subproblem
dp[i + 2] = the most loot from houses 0..i.
Relation
dp[i + 2] = max(dp[i + 1], dp[i] + nums[i]): skip or rob.
Order
left to right: each cell reads the two before it.
Base, answer
dp[0] = dp[1] = 0 (no houses); the answer is dp[-1].

What stays true

Before house i, every cell dp[0..i + 1] holds the true best for its prefix.

Why each move is safe

  • In any best plan for houses 0..i, house i is robbed or it isn't. Not robbed: the rest is a best plan for 0..i − 1. Robbed: house i − 1 isn't, so the rest is a best plan for 0..i − 2.
  • Both of those cells were filled earlier, so max of the two choices is the best for 0..i.
  • Each cell is filled once from two lookups: O(n), where plain recursion branches twice per house: O(2ⁿ).

Relies on: optimal substructure (a best plan's parts are best plans) and overlapping subproblems. If the choice at i depended on more than the last two houses, the state would need more.

Best ending here: read every earlier cell

LIS: dp[i] = 1 + max(dp[j]) over j < i with smaller values. Maximum product keeps the largest and the smallest product ending at i.

Reachable sums

Partition Equal Subset Sum: a set (or boolean row) of sums reachable with the items so far; each item adds itself to every sum already there.

Count the work

Count how often each line runs; the line with the most runs decides the Big-O. Here that is dp[i + 2] = max(dp[i + 1], dp[i] + money).

Each cell is written once, from two reads: n runs at O(1). The coin table writes amount cells and tries each coin for each, so its inner line runs amount × coins times: O(amount × coins). Plain recursion without the table branches at every cell: O(2ⁿ) for the houses.

Where it breaks

  • No subproblem written in words is how wrong relations happen. Write dp[i] = ... in a sentence first.
  • Reading a cell that isn't filled yet means the order is wrong for the relation.
  • Base cases that don't mean anything like dp[0] = 1 for coins without saying 'one way to make 0'.
  • Loop order for counting amounts outside, coins inside counts ordered sequences (Combination Sum IV); coins outside counts combinations (Coin Change II).
