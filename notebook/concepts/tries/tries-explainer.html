Tries, explained

A tree of characters where every node is a prefix. Words that share a beginning share a path, so a prefix lookup costs the length of the prefix, however many words are stored.

Spot it

A trie (prefix tree) stores words letter by letter: the root is the empty prefix, each edge adds one character, and a marker says where a whole word ends. Looking up a word or a prefix walks one edge per character: O(L), independent of how many words there are.

Reach for it when the questions are about prefixes (autocomplete, "does any word start with..."), when a wildcard must try several letters, or when many words are searched at once, as on a letter grid, so a dead prefix stops every word that shares it. For plain membership, a hash set is simpler.

Ask yourself

  1. Are the questions about prefixes? Starts-with, autocomplete, the shortest root of a word.
  2. Do many words share work? Searching all of them on one grid: walk the trie and the grid together.
  3. Is there a wildcard? At a ., try every child: DFS through the trie.
  4. What marks a whole word? An end flag, so that 'car' isn't found just because 'cart' is stored.

Looks like it, isn't

  • Exact membership only. A hash set: same O(L) per lookup, far less memory.
  • Substring search in one long text. A trie of prefixes doesn't help; KMP, rolling hashes or a suffix structure do.
  • Anagram groups. Order of letters doesn't matter: hash the sorted word or the letter counts.

The parts

Names

root
the empty prefix: a dict from a first letter to a child node
node
the prefix read so far; its keys are the letters that can come next
"$"
the end marker: a whole word ends at this node

Your plan card

Insert
from the root, follow each letter, creating a node when it's missing; mark the last node with $.
Search
follow each letter; a missing letter means no such word or prefix.
Word or prefix?
at the end, a word needs $; a prefix needs only to have got there.
Cost
one step per character: O(L) for a word of length L.

What stays true

Every node stands for the prefix spelled on the path from the root to it, and it carries $ exactly when that prefix is an inserted word.

Why each move is safe

  • Two words share the nodes of their common prefix and no more, so inserting one never changes another's path.
  • setdefault(ch, {}) reuses an existing child, so the same prefix is never stored twice.
  • A search that falls off the trie at letter i proves no stored word starts with those i + 1 letters.

Relies on: a small alphabet per node and shared prefixes. With few shared prefixes, a trie is mostly overhead compared with a hash set.

Implement Trie (Prefix Tree) medium

Wildcards: branch at '.'

A DFS over (node, index): a letter follows one child, a '.' tries every child. Shared prefixes are explored once.

def match(node, word, i):
    if i == len(word):
        return "$" in node
    if word[i] == ".":
        return any(match(child, word, i + 1) for ch, child in node.items() if ch != "$")
    return word[i] in node and match(node[word[i]], word, i + 1)

Count the work

Count how often each line runs; the line with the most runs decides the Big-O. Here that is node = node.setdefault(ch, {}).

The inner line runs once per character inserted, so its runs are the total length of the words, and each run is one dict operation. A search runs it at most once per character of the query: O(L), whether the trie holds ten words or a million.

Where it breaks

  • No end marker reports 'car' as stored when only 'cart' is.
  • A mutable default for children (children={}) makes every node share one dict.
  • Word Search II without pruning found words reports a word once per path and keeps searching dead branches.
  • A trie for exact membership only costs memory and code for what a set does.
