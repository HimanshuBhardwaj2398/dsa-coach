Advanced Graphs, explained

BFS with a heap instead of a queue. Always expand the cheapest frontier entry next; with non-negative weights, the first time a node comes off the heap its cost is final.

Spot it

When edges have costs, BFS's 'fewest edges' is the wrong measure. Dijkstra keeps a min-heap of (cost so far, node) and always expands the cheapest. Because no edge is negative, nothing found later can beat a node's cost once it is popped: it is settled. Entries that were pushed before a cheaper route turned up stay in the heap as stale entries and are skipped when popped.

The same loop with a different key builds a minimum spanning tree (Prim: key = the edge's own cost, not the path's). Other members change what a state is: (node, stops used) for 'at most k stops', where Bellman-Ford's k rounds of relaxing every edge fit better; letters as nodes for an alien alphabet (topological order); each edge used once for an itinerary (Hierholzer).

Ask yourself

  1. Are there weights, and can they be negative? Non-negative: Dijkstra. Negative: Bellman-Ford.
  2. Shortest path, or cheapest way to connect everything? Path: Dijkstra. Connect all: a minimum spanning tree (Prim or Kruskal).
  3. Is there an extra limit (stops, fuel, time)? Make it part of the state, or run Bellman-Ford for exactly k rounds.
  4. What is the cost of a path: a sum or a maximum? Swim in Rising Water: the max along the path; the heap still works.

Looks like it, isn't

  • Equal weights everywhere. Plain BFS: same answer, no log factor.
  • Negative edge weights. A settled node could still be improved: Bellman-Ford.
  • Shortest paths between every pair, n ≤ 100. Floyd–Warshall's triple loop is simpler than n runs of Dijkstra.

The parts

Names

heap
(cost so far, node) entries, cheapest first; it may hold old, stale entries
dist
the best cost found so far for each reached node
done
settled nodes: popped once, cost final

Your plan card

Start
dist = {start: 0}, heap = [(0, start)].
Pop
the cheapest entry; if its node is already settled, it is stale: skip it.
Settle and relax
mark the node done; for each edge, if d + w beats dist[nxt], record it and push it.
Stop
the heap is empty: dist holds the cost of every reachable node.

What stays true

Every settled node's dist is its true cheapest cost, and every heap entry is a real path's cost.

Why each move is safe

  • When the cheapest entry (d, node) is popped, every other route to node goes through some entry still in the heap, which costs at least d; edges add ≥ 0, so no route beats d. Settle it.
  • A node can be pushed several times as cheaper routes appear. Only its cheapest entry is popped first; later ones are stale and skipped.
  • Each edge is relaxed once, when its tail is settled, so the heap gets at most E pushes.

Relies on: non-negative edge weights. One negative edge can make a settled cost wrong.

A limit on stops

Bellman-Ford for k + 1 rounds, each relaxing every edge from a copy of the previous round's costs, so a round adds at most one flight.

cost = {src: 0}
for _ in range(k + 1):
    nxt = dict(cost)                 # relax from last round's costs only
    for a, b, price in flights:
        if a in cost and cost[a] + price < nxt.get(b, float("inf")):
            nxt[b] = cost[a] + price
    cost = nxt
return cost.get(dst, -1)

Each node is settled once, and settling it relaxes each of its outgoing edges once, so the relax check runs at most E times. Each run may push onto the heap, which costs O(log E), and every pushed entry is popped once, also O(log E). Runs × cost: O(E log E), usually written O(E log V).

Where it breaks

  • Marking a node done when it is pushed settles it before a cheaper route is found. Settle on pop.
  • No stale check re-expands a node from an old, larger cost: still correct, but slower; with the check, each node is expanded once.
  • Negative weights break the settle-on-pop proof. Use Bellman-Ford.
  • Dijkstra for 'at most k stops' prunes a costlier route that would have fitted the stop limit. Put stops in the state, or use k + 1 Bellman-Ford rounds.
