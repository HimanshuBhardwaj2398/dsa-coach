Bit Manipulation, explained

Treat an integer as a row of bits. A few identities do the work: x ^ x = 0 cancels pairs, and x & (x − 1) clears the lowest set bit.

Spot it

Bit problems look like tricks, but each rests on one identity you can check on paper. XOR is addition without carries: x ^ x = 0 and x ^ 0 = x, in any order, so XOR-ing a list cancels every value that appears twice. x & (x − 1) turns off the lowest 1 bit (subtracting 1 flips that bit and every 0 below it), so a loop of it runs once per set bit. x & 1 reads the lowest bit; x >> 1 drops it.

Reach for bits when a problem says 'appears twice except one', 'missing number', 'count the 1s', 'without + or −', or 'all subsets of n ≤ 20' (each subset is an n-bit mask). Python's integers never overflow, so 32-bit behaviour (negative numbers, the sign bit) needs an explicit mask: & 0xFFFFFFFF.

Ask yourself

  1. Do equal values need to cancel? XOR them all: pairs vanish, the odd one out remains.
  2. Do I need the set bits one at a time? n & (n − 1) drops the lowest; n & -n isolates it.
  3. Is a subset small enough to be a mask? n ≤ 20: loop masks 0..2ⁿ − 1, bit i means item i is in.
  4. Does 32-bit overflow matter? Mask with 0xFFFFFFFF, and convert values ≥ 2³¹ back to negative.

Looks like it, isn't

  • Every value appears three times except one. XOR alone fails; count each bit position mod 3.
  • Two values appear once. XOR everything, then split the values by any set bit of the result and XOR each group.
  • Large numbers as strings. That's digit arithmetic, not bits.

What stays true

acc is the XOR of the values processed so far, which equals the XOR of those that have appeared an odd number of times.

Why each move is safe

  • XOR works bit by bit: each output bit is 1 when an odd number of inputs have a 1 there.
  • A value seen twice contributes its 1s twice to every bit, an even count, so it vanishes from acc.
  • Only the single value has an odd count, so acc ends equal to it.

Relies on: every other value appearing an even number of times. With triples, XOR leaves the wrong answer.

Count the work

Count how often each line runs; the line with the most runs decides the Big-O. Here that is n &= n - 1.

The loop runs once per set bit, never more than the number of bits. These inputs are all 1s, the worst case: 8, 16, 32, 64 turns. A loop that shifts one bit at a time always runs once per bit, even for a number with a single 1. Single Number is one XOR per value: O(n).

Where it breaks

  • x & 1 == 0 parses as x & (1 == 0). Write (x & 1) == 0.
  • ~x expecting a 32-bit flip in Python, ~x is -x - 1. Mask with 0xFFFFFFFF.
  • Negative numbers with >> Python's shift keeps the sign and never stops for -1. Mask first.
  • XOR when values appear three times leaves garbage. Count each bit position mod 3.
