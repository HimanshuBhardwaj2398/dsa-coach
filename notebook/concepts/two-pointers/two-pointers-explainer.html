Two Pointers, explained

Two indices close in from both ends. Each comparison proves that every pair using one of them is finished, so the n² pairs take at most n − 1 steps.

Spot it

Reach for two pointers when the candidates are pairs and one comparison can rule out every pair that uses one element. Sorted order gives that proof for sums, mirror symmetry gives it for palindromes, and the shorter wall gives it for container area.

Draw the candidates as the upper triangle of an n × n grid: cell (i, j) is the pair i < j. Brute force reads every cell. Two pointers stand on one cell and, with one comparison, grey out a whole row or column.

Ask yourself

  1. What are the candidates? Pairs (i, j) with i < j, or a pair inside a triple once one index is fixed.
  2. What does one comparison prove? If the sum is too small, the left element with any partner up to r is smaller still.
  3. Which element is finished? Move that pointer, and only that one.
  4. What must I keep? Usually just l, r and the best so far: O(1) extra space.

Pick what you would reach for. A wrong pick shows the gap; pick again to move on.

Looks like it, isn't

  • Pair sum on an unsorted array. No order, so no proof: use a hash map, or sort first when the indices don't matter (n log n).
  • Subarray sum equals k, with negative numbers. Contiguous ranges and negatives: neither end can be ruled out. Prefix sums with a hash map.
  • Count the pairs with sum below a target. Still two pointers, but when nums[l] + nums[r] < target all r − l pairs (l, l+1..r) count at once.

The parts

Names

l
the smallest index still in play
r
the largest index still in play
s
nums[l] + nums[r], the one pair being checked

Your plan card

Start
l = 0, r = n - 1: every pair is in play.
Continue
while l < r: at least one pair is left.
Move
s < target: l += 1. s > target: r -= 1. Equal: return the pair.
Stop
l meets r: no pair is left, so there is none.

What stays true

Any pair that sums to the target lies inside [l..r]. Every pair with an index outside has been ruled out.

Why each move is safe

  • If s < target: for every j ≤ r, nums[l] + nums[j] ≤ nums[l] + nums[r] < target, so no answer uses index l. Drop it: l += 1.
  • If s > target: for every i ≥ l, nums[i] + nums[r] ≥ s > target, so no answer uses index r. Drop it: r -= 1.
  • Progress: r - l shrinks by one every turn, so the loop ends.

Relies on: ascending order. On an unsorted array the first bullet is false: one small sum proves nothing about other pairs.

The family

Opposite-end pointers are one member of a family. Every member makes the same move: one comparison proves an element is finished.

Two Sum II - Input Array Is Sorted medium

Fix one, pair the rest

Sort, fix nums[i], then run the pair search on the part to its right for -nums[i]. Skip a fixed value equal to the one before it, and after a find move both pointers past equal values, so no triple repeats.

n fixed values × at most n pair steps: O(n²), which beats the n³ of all triples.

3Sum medium

Move the limiting side

Area is min(h[l], h[r]) * (r - l). The shorter wall caps every pair it makes with anything inside, and those pairs are narrower, so the shorter wall is finished: move it.

Where it breaks

  • while l <= r lets l equal r, pairing an element with itself.
  • Moving both pointers after a miss skips pairs nothing has ruled out. Only the finished side moves.
  • Running it on unsorted input breaks the proof. Sort first and lose the original indices, or use a hash map.
  • 3Sum without skipping equal values returns the same triple more than once.
