Graphs, explained

Nodes and the links between them, with cycles allowed. Every graph algorithm here is a walk that never re-enters a node: BFS for fewest steps, DFS for reaching everything, Kahn's order for prerequisites.

Spot it

A graph problem is often in disguise: grid cells linked to their four neighbours, words one letter apart, courses and their prerequisites, accounts sharing an email. Name the nodes and the edges first; the algorithm usually follows.

Then choose the walk. BFS (a queue) reaches nodes in order of distance, so the first time it reaches a node is by the fewest edges. DFS (recursion or a stack) is enough when you only need to reach everything: flood fill, components, cycles. Topological order (Kahn: repeatedly take a node with no unmet prerequisites) orders a directed graph, and fails exactly when there is a cycle. Union-find merges components as edges arrive.

Ask yourself

  1. What are the nodes and the edges? Cells and their neighbours; words and one-letter changes; courses and prerequisites.
  2. Fewest steps, or just reachable? Fewest steps on unweighted edges: BFS. Reachable or count of components: DFS or union-find.
  3. Directed with dependencies? Topological order. Fewer nodes come out than went in: there is a cycle.
  4. When is a node marked visited? When it is added to the queue, not when it is taken off, so it is queued once.

Looks like it, isn't

  • A tree. A graph with no cycles and one path between nodes: plain recursion works, no visited set needed.
  • Shortest path with weights. BFS is only for unweighted (or equal-weight) edges. Use Dijkstra.
  • A grid DP like unique paths. Moves only right and down, so no cycles: the order is fixed and DP fills it.

The parts

Names

nodes reached but not yet expanded, in the order they were reached

the node being expanded, and the neighbour being looked at

Your plan card

Start
dist = {start: 0}, queue = [start].
Expand
take the node at the front of the queue.
Each neighbour
not in dist yet: dist[nxt] = dist[node] + 1, and queue it.
Stop
the queue is empty: every reachable node has its distance.

What stays true

The queue holds nodes in order of distance, and its first and last differ by at most 1. So when a node is first reached, it is by the fewest edges.

Why each move is safe

  • Nodes leave the queue in order of distance d, d, ..., d + 1, d + 1. A neighbour first reached from a node at distance d can't be reached in fewer than d + 1 edges, or it would have been reached from an earlier node.
  • Marking a node when it is queued (adding it to dist) stops it from being queued twice, so each node is expanded once and each edge looked at once per direction.
  • The queue only grows with nodes not in dist, so the loop ends.

Relies on: unweighted edges: one edge, one step. With weights, a path of more edges can be cheaper, and BFS order breaks.

Components and cycles with union-find

find with path compression and union by size; an edge whose ends share a root closes a cycle. A tree is n − 1 edges and no cycle.

parent = list(range(n))

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]  # path halving
        x = parent[x]
    return x

def union(a, b):
    ra, rb = find(a), find(b)
    if ra == rb:
        return False                   # already connected: this edge closes a cycle
    parent[ra] = rb
    return True

Where it breaks

  • Marking visited when a node leaves the queue lets it be queued many times; on a dense graph that is far more work. Mark when queuing.
  • Recursive DFS on a 10⁶-cell grid can pass Python's recursion limit. Use BFS or an explicit stack.
  • Starting from one node only misses the other components. Loop over every node and start from each unvisited one.
  • BFS on weighted edges returns the fewest edges, not the cheapest path.
