Prefix Sums, explained

Any range sum is a difference of two running totals. Store the totals you have passed, and a question about every subarray ending here becomes one lookup.

Spot it

A prefix sum P[i] is the sum of the first i values, with P[0] = 0. The sum of nums[l..r] is P[r + 1] - P[l]: two running totals, one subtraction.

That turns "which subarrays sum to k?" into "which earlier totals equal total - k?". A hash map from total to how often it appeared answers that for every subarray ending at the current index, in one lookup. Unlike a sliding window, it doesn't care whether values are negative.

Ask yourself

  1. Is the question about contiguous ranges? Sums, counts or remainders of nums[l..r].
  2. Can the range be written as a difference? sum(l..r) = P[r + 1] - P[l], so fix the end and look up the start.
  3. What do I look up? The earlier total that would make the difference right: total - k, or the same remainder mod k.
  4. Count, earliest index, or just existence? That decides what the map stores: counts, first index, or a set.

Looks like it, isn't

  • Maximum subarray sum. Prefix sums work (subtract the smallest total so far), but Kadane's running sum is the same idea with less to keep.
  • Positive values and a target sum. A sliding window answers it in O(1) extra space; save the map for when values can be negative.
  • A sum over a non-contiguous choice. Subsets aren't ranges: that is DP or backtracking.

The parts

Names

total
the prefix sum through the current index: P[i + 1]
seen
how many times each earlier total has appeared, starting with {0: 1} for the empty prefix
total - k
the earlier total a subarray ending here would need to start after

Your plan card

Start
seen = {0: 1}, total = count = 0.
Each value
add it to total; add seen[total - k] to count; then record total in seen.
Order
count before recording, so a subarray is never empty.
Stop
after the last value: count holds every subarray.

What stays true

Before the lookup at index i, seen holds the totals P[0..i], and count holds the subarrays inside nums[:i] that sum to k.

Why each move is safe

  • A subarray nums[j..i] sums to k exactly when P[i + 1] - P[j] = k, that is when P[j] = total - k. So seen[total - k] is the number of subarrays ending at i.
  • seen starts with {0: 1} because P[0] = 0: a subarray that starts at index 0 needs it.
  • Recording total after the lookup keeps j ≤ i: the current total can only start later subarrays.

Relies on: addition being undone by subtraction. It works for any integers, negative ones included. For products, zeros break the division; use prefix and suffix products instead.

Where it breaks

  • Starting with an empty map misses every subarray that starts at index 0. seen = {0: 1}.
  • Recording before looking up counts the empty subarray when k = 0.
  • A sliding window with negative values has no rule for which end to move; totals do.
  • P[r] - P[l] for nums[l..r] drops the last value. With P[0] = 0 it is P[r + 1] - P[l].
