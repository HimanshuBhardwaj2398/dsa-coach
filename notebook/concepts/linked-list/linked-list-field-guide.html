A node is a value plus an address

Each node stores its data and a reference to the next node. The list itself is only a reference to the first node, head. The last node points to None. There is no index and no block of memory, so every operation is about following and rewiring references.

That's why linked list code comes down to two questions: which node am I standing on, and which pointers change. Draw the boxes and arrows before you code, and say which arrows move.

Keeping a tail reference makes append O(1). Keeping a size counter makes len() O(1). Both cost one field each, and every operation has to keep them correct. That's the trade-off in miniature: extra state buys speed but adds invariants to maintain.

class Node:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next

class LinkedList:
    def __init__(self):
        self.head = None
        self.tail = None
        self.size = 0

    def prepend(self, val):          # O(1)
        self.head = Node(val, self.head)
        if self.tail is None:
            self.tail = self.head
        self.size += 1

    def append(self, val):           # O(1) thanks to tail
        node = Node(val)
        if self.tail is None:
            self.head = self.tail = node
        else:
            self.tail.next = node
            self.tail = node
        self.size += 1

    def delete(self, val):           # O(n): find the node BEFORE it
        dummy = Node(0, self.head)
        prev = dummy
        while prev.next and prev.next.val != val:
            prev = prev.next
        if prev.next is None:
            return False
        if prev.next is self.tail:
            self.tail = None if prev is dummy else prev
        prev.next = prev.next.next
        self.head = dummy.next
        self.size -= 1
        return True

    def __iter__(self):              # for x in my_list
        node = self.head
        while node:
            yield node.val
            node = node.next

Singly linked

Only next. Uses the least memory, but you can't step backwards. To delete a node you need the one before it.

Doubly linked

Has prev and next. You can remove any node you hold in O(1). Used by LRU caches, deque, and the Linux kernel's list_head.

Circular

The tail points back to the head. Good for round-robin scheduling and playlists on repeat. Loops need a stop condition other than None.

Arrays win on reading, linked lists win on rewiring

Same 4 values in the same 16 memory cells

Array: neighbours in memory. The address of a[i] is start + i × size.

Linked list: scattered. Each node stores the address of the next one.

Walking the linked list means jumping 0x02 → 0x0D → 0x06 → 0x0B. Each jump can miss the CPU cache, while an array scan streams neighbouring cells in together.

What this means in Python

A Python list is a dynamic array of references, so insert(0, x) and pop(0) are O(n). collections.deque is a doubly linked list of 64-slot blocks, which gives O(1) at both ends and is the right queue for BFS. OrderedDict and functools.lru_cache pair a hash map with a doubly linked list. You rarely write a linked list in Python application code, but you use one all the time. The default rule: use a list, and reach for a linked structure when the work is mostly at the ends, or when you already hold a node and need to move it in O(1).

Where linked lists actually run

Each of these needs O(1) restructuring at a position it already knows, which is the one thing arrays can't do cheaply.

Five patterns cover most linked list problems

Learn these as moves, not as solutions to memorise. Almost every problem below combines two of them.

1. Dummy head

Put a fake node before head, so that deleting or inserting at the front is no longer a special case. Return dummy.next.

dummy = tail = Node(0)
while a and b:
    if a.val <= b.val: tail.next, a = a, a.next
    else:              tail.next, b = b, b.next
    tail = tail.next
tail.next = a or b
return dummy.next          # merge two sorted lists

2. Reverse in place

Three pointers, and the order matters: save next first, then flip, then advance. Reversing is also a building block for palindrome checks, reorder list and k-group problems.

prev, cur = None, head
while cur:
    nxt = cur.next       # 1. remember the way forward
    cur.next = prev      # 2. flip the arrow
    prev, cur = cur, nxt # 3. step forward
return prev

3. Fast and slow pointers

Moving at 1 and 2 steps finds the middle and detects cycles (Floyd's algorithm). Once both pointers are inside a cycle, the gap between them shrinks by exactly 1 per step, so they're guaranteed to meet within μ + λ steps, where μ is the number of steps from head to the cycle's first node and λ is the cycle's length.

slow = fast = head
while fast and fast.next:   # guard both hops
    slow, fast = slow.next, fast.next.next
    if slow is fast:
        return True         # cycle
return False                # slow is the middle if no cycle

4. Fixed gap runner

Move one pointer k steps ahead, then move both together. When the leader reaches the end, the follower is k from the end. This finds the nth node from the end in one pass.

dummy = Node(0, head)
lead = follow = dummy
for _ in range(n + 1):
    lead = lead.next
while lead:
    lead, follow = lead.next, follow.next
follow.next = follow.next.next   # remove nth from end
return dummy.next

5. Hash map plus doubly linked list

The map finds a node in O(1), and the list moves or removes it in O(1). This is the design behind LRU caches. It's the pattern most relevant to architecture work, because it shows two simple structures combining to meet a requirement neither meets alone.

def get(self, key):
    if key not in self.map:
        return -1
    node = self.map[key]
    self._unlink(node)       # O(1) thanks to node.prev
    self._push_front(node)   # most recently used
    return node.val

Loop discipline

Before writing any while, answer four questions. What state am I tracking? What must be true to take the next step safely? That's the guard, and it should cover every .next you dereference. How do I exit early with the answer? What does a normal exit mean? The loop condition says can I continue, and the body says did I find it.
