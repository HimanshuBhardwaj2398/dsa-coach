Linked List, explained

A list you can only walk forward. Every technique comes down to rewiring next pointers in a safe order, and to walking with more than one pointer.

Spot it

A linked list gives O(1) splicing at a node you already hold, and no random access: reaching index i costs i steps. So the problems are about pointer order: which next you must save before you overwrite it, and which node you must keep a handle on so nothing becomes unreachable.

Three moves cover most of them: rewire with prev and curr (reverse, reorder), walk with two speeds or a gap (middle, cycle, n-th from the end), and build behind a dummy head (merge, remove), so the first node is not a special case.

Ask yourself

  1. What must stay reachable? Before curr.next = ..., save curr.next if you still need the rest.
  2. Do I need a node before the head? If the head can change or be removed, start from a dummy node.
  3. Would two pointers at different speeds find it? Middle: slow 1, fast 2. Cycle: they meet. n-th from the end: a gap of n.
  4. In what order do the pointer writes happen? Write them down first; most bugs are two lines swapped.

Which fits?

Pick what you would reach for. A wrong pick shows the gap; pick again to move on.

Looks like it, isn't

  • Find the duplicate number in an array of n + 1 values in 1..n. No list in sight, but i → nums[i] is one: Floyd's cycle finding on indices.
  • Reverse an array. Two pointers swapping from both ends; there are no next pointers to rewire.
  • Merge k sorted lists. The splice is a linked list move, but choosing the smallest head each time is a heap.

The parts

Names

prev
the head of the part already reversed (None at first)
curr
the first node not yet reversed
nxt
a saved handle on curr.next, taken before that pointer is overwritten

Your plan card

Start
prev = None, curr = head.
Continue
while curr: nodes are left to reverse.
Move
save nxt = curr.next; point curr.next = prev; step prev, curr = curr, nxt.
Stop
curr is None; prev is the new head.

What stays true

prev heads the reversed part and curr heads the rest. Together they hold every node, and nothing is unreachable.

Why each move is safe

  • nxt = curr.next comes first: once curr.next = prev runs, it is the only handle on the rest of the list.
  • curr.next = prev adds one node to the front of the reversed part; the rest is still reachable through nxt.
  • prev, curr = curr, nxt restores the invariant for one more reversed node, so the loop ends after n turns.

Relies on: the order of the three writes. Swap any two and a node becomes unreachable or the list loops.

Build behind a dummy head

dummy = tail = ListNode(0); append to tail; return dummy.next. For k lists, keep their heads in a heap.

Merge Two Sorted Lists easy · Add Two Numbers medium · Merge k Sorted Lists hard

Two speeds

slow moves 1, fast moves 2. They meet inside a cycle; when fast reaches the end, slow is in the middle. Reorder List = find the middle, reverse the second half, weave.

Linked List Cycle easy · Find the Duplicate Number medium · Reorder List medium

A gap of n

Start the lead n steps ahead of the trailer; move both until the lead ends. Begin at a dummy head so removing the first node works too.

Remove Nth Node From End of List medium

A map from node to node

Copy with random pointers: map each old node to its copy in one pass, wire next and random in a second. LRU: a map to doubly linked nodes.

Where it breaks

  • curr.next = prev before saving curr.next loses the rest of the list.
  • Returning head returns the old first node, now the last. The new head is prev.
  • fast.next.next without checking fast.next crashes on an even-length list. Loop while fast and fast.next.
  • No dummy head makes removing or replacing the first node a special case.
