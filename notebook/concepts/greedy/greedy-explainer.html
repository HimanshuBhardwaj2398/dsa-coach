Greedy, explained

Make the choice that looks best now, never revisit it, and prove that choice can always be swapped into some optimal answer. The proof is the whole pattern; the code is usually one loop.

Spot it

A greedy algorithm commits to one local choice per step: the farthest reach, the interval that ends first, dropping a running sum once it turns negative. It is fast and short, and wrong unless you can say why. The usual proof is an exchange argument: take any optimal answer, swap in the greedy choice, and show it is no worse.

So reach for greedy when one quantity summarises everything the future needs (a farthest index, a running sum, the earliest end), and test it on a small counterexample before trusting it. Coins of 1, 3 and 4 for amount 6 is the classic warning: largest-first takes 4 + 1 + 1, but 3 + 3 is better. That is DP.

Ask yourself

  1. What one number summarises the past? The farthest reachable index; the best sum ending here; the fuel left.
  2. What is the greedy choice? Extend the reach; restart the sum; take the interval that ends first.
  3. Why can it always be swapped into an optimal answer? Say the exchange argument in one sentence, or don't use greedy.
  4. Is there a small counterexample? Try 3–4 elements by hand; if the greedy choice loses, it is DP.

Which fits?

Pick what you would reach for. A wrong pick shows the gap; pick again to move on.

Looks like it, isn't

  • Coin change with arbitrary coins. Largest-first fails on [1, 3, 4] for 6: DP.
  • 0/1 knapsack. Best value per weight first fails; fractional knapsack is the greedy one.
  • Weighted intervals. Earliest end works only without weights; with weights it is DP.

The parts

Names

reach
the farthest index reachable using indexes 0..i
i
the index being considered
i + step
how far a jump from i can go

Your plan card

Start
reach = 0: only index 0 is reachable.
Each index
if i > reach, it can't be reached, and nothing after it can: return False.
Otherwise
reach = max(reach, i + step).
Stop
every index was reachable: True.

What stays true

Before index i is checked, every index ≤ reach is reachable, and no index > reach is reachable using jumps from 0..i − 1.

Why each move is safe

  • Reachable indexes form a prefix: if j is reachable, so is every index before j (jump shorter). So one number, the farthest reach, describes them all.
  • If i > reach, no jump from any earlier index lands on i or beyond: the end is unreachable.
  • Taking the max keeps the reach true after index i: a jump from i adds exactly [i, i + step].

Relies on: the reachable set being a prefix. If some jumps were forbidden landing squares, it wouldn't be, and greedy would break.

Where it breaks

  • Greedy without a proof passes the examples and fails the hidden tests. Try a 3–4 element counterexample first.
  • Kadane starting from best = 0 returns 0 for an all-negative array. Start from nums[0].
  • Gas Station without the total check returns a start even when no full loop exists.
  • Jump Game II counting every reach update as a jump overcounts; count only when the current range ends.
